Operating Systems project · FUSE 3 · C11 · pthreads

Small files stay quick while big copies run.

SchedFS is a mountable Linux file system for shared workspaces where large background transfers and everyday file operations happen at the same time. Every block it reads or writes becomes a request in one queue, and one dispatcher thread serves them in the order chosen by a disk-scheduling policy. The deadline policy serves overdue requests first and otherwise the nearest block, to keep small operations responsive while bulk copies keep running.

Maximum file size

(12 + 1024) blocks × 4 KiB = 1036 blocks, about 4.05 MiB. Reads of unallocated blocks return zeros, so sparse files and truncate to a larger size work.

02 · Policies

Six ways to choose the next request

All six share deterministic tie-breaking: earlier arrival first, then lower request ID. The same trace always produces the same service order. FCFS, SSTF, SCAN and LOOK are the textbook algorithms; deadline scheduling is an established approach (the Linux deadline I/O scheduler also gives reads and writes separate expiry times).

PolicyPicks nextStrengthWeakness
FCFSThe oldest requestFair, no starvationIgnores where the head is
SSTFThe block closest to the headShort seeksFar requests can starve
SCANThe closest block in the current direction; travels to the disk edge before reversingEven sweep, bounded waitExtra trip to the edge
LOOKSame choice as SCAN, but reverses at the last requestNo trip to the edgeRequests just behind the head wait a sweep
AdaptiveThe lowest score that combines distance and ageTunable between SSTF and FCFSNo starvation guarantee: the age term is worth at most β
DeadlineOverdue requests first (earliest deadline), otherwise the closest block. Deadline = arrival + 0 ms for reads, + 2 ms for writes (defaults, tuned)Reads are not overtaken by nearby writes; writes keep locality until their own deadlineNot a real-time guarantee; under overload it becomes earliest-deadline-first
Adaptive: score = α · distance / total_blocks − β · wait / max_wait

With β = 0 Adaptive is exactly SSTF. Because the age term is divided by the oldest wait, it never exceeds β, so a request more than (β/α) × N blocks farther than nearby work is never chosen while nearby work keeps arriving.

04 · Measured results

Small files during big copies: six policies, measured

Mounted SchedFS, fresh image per run, identical workload and seeds for every policy, 3 runs × 10 s per bar (about 1,500 timed operations). Foreground: open + 4 KiB read or update + close of a small file every 20 ms. Background: 2 or 4 processes writing or copying 2 MiB files. direct = real I/O with O_DIRECT (no modeled delay); model = the same plus a modeled seek time of 100 µs + 0.25 µs per block moved. From results/mounted/summary.csv.

Small reads stay quick

p99 of small reads during background writes or copies: 22–56% lower than FCFS and 30–79% lower than SSTF.

The cost

Against SSTF, 20–60% less background throughput on the modeled-seek disk. Against FCFS, within −13% to +15%.

Where it does not win

Small updates on real O_DIRECT I/O: 24% worse p99 than FCFS. Four writers on the modeled disk: LOOK slightly better.

One Windows 11 + WSL 2 machine. The "model" configuration models a disk; it is not a physical hard disk. SCAN's bars are high on the model disk because every reversal pays the modeled trip to the disk edge. Method, tuning and full tables: docs/evaluation.md. The scheduler lab above is a separate, simulated clock.

05 · Run it

Try it

On Ubuntu 22.04 or 24.04 (or WSL 2) with libfuse3-dev and fuse3 installed:

# build, format a 64 MiB image, mount with the deadline policy
make
./mkfs.schedfs disk.img 64M
mkdir -p mnt && ./schedfs disk.img mnt --sched=deadline

# it is a real directory
mkdir mnt/project
echo 'Operating Systems' > mnt/project/notes.txt
cat mnt/project/notes.txt
fusermount3 -u mnt

# the 5-minute demo, the tests, and the measurements above
scripts/demo.sh
make test
python3 scripts/experiments.py matrix results/mounted/matrix && python3 scripts/report_results.py results/mounted
SchedFS is a teaching file system: no journal, no crash recovery, no cache. It keeps small file operations responsive during bulk transfers by scheduling block requests with deadlines, and measures the trade-off.
