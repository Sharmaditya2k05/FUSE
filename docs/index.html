Operating Systems project · FUSE 3 · C11 · pthreads

A file system where every block waits its turn.

SchedFS is a mountable Linux file system. Each block it reads or writes becomes a request in a shared queue, and one dispatcher thread services those requests in the order chosen by a disk-scheduling policy: FCFS, SSTF, SCAN, or an age-aware Adaptive policy.

01 · Architecture

The path of one cat file.txt

Requests flow strictly downward. After mount, only the dispatcher thread ever calls pread or pwrite on the image, so the scheduler controls every byte of disk I/O.

Each caller sleeps on its own condition variable until the dispatcher marks its request complete. That is what lets many file-system threads queue up at once, giving the scheduler something to reorder.

Maximum file size

(12 + 1024) blocks × 4 KiB = 1036 blocks, about 4.05 MiB. Reads of unallocated blocks return zeros, so sparse files and truncate to a larger size work.

02 · Policies

Four ways to choose the next request

All four share deterministic tie-breaking: earlier arrival first, then lower request ID. The same trace always produces the same service order.

PolicyPicks nextStrengthWeakness
FCFSThe oldest requestFair, no starvationIgnores where the head is
SSTFThe block closest to the headShort seeksFar requests can starve
SCANThe closest block in the current direction, reversing at the disk edgeEven sweep, bounded waitExtra trip to the edge
AdaptiveThe lowest score that combines distance and ageTunable between SSTF and FCFSExperimental
score = α · distance / total_blocks − β · wait / max_wait

With β = 0 it is exactly SSTF. Raising β lets requests that have waited longer jump the queue.

04 · Measured results

Benchmark: five traces, four policies

From benchmark.csv, produced by make bench. Every policy replays the identical trace. Seek distances are exact; times use a seek-delay model of 10 µs plus 2 µs per block moved.

FCFS loses badly under contention

On the concurrent trace it moves the head 27,402 blocks; SSTF and Adaptive need 4,029.

SCAN is the fairest

Lowest average and maximum wait on the concurrent trace, because nothing is left stranded behind the head.

No policy wins everywhere

On clustered requests SCAN is worst: it sweeps to the disk edge even though every request is nearby.

Traces are short (7 to 16 requests), so timing columns vary from run to run by a few milliseconds; seek distance is the stable comparison. The mounted file system records the same metrics from real FUSE traffic.

05 · Run it

Live demo in four commands

On Ubuntu 22.04 or 24.04 (or WSL 2) with libfuse3-dev and fuse3 installed:

# build, format a 16 MiB image, mount with SSTF
make
./mkfs.schedfs disk.img 16M
mkdir -p mnt && ./schedfs disk.img mnt --sched=sstf

# in a second terminal: it is a real directory
mkdir mnt/project
echo 'Operating Systems' > mnt/project/demo.txt
cat mnt/project/demo.txt
stat mnt/project/demo.txt
fusermount3 -u mnt

# reproduce the numbers above and run every test
make bench && python3 scripts/plot_results.py
make test
SchedFS is a teaching file system: no journal, no crash recovery, no cache. Built to make the trade-offs between disk-scheduling policies visible on real file-system traffic.
